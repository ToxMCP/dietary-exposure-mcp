# Dietary Exposure MCP v0.2.0 candidate

This candidate migrates the server to the stable Python MCP SDK 2.2.0 and the
2026-07-28 protocol while preserving SDK v1 clients. Modern clients can use
discovery, independent HTTP requests and private catalog caching. Existing
hosts retain stdio commands, legacy handshakes and the `/mcp` endpoint.

The Python server API now returns `MCPServer`; SDK result attributes use
snake_case and `call_tool()` returns a result object. HTTP options belong to
`create_http_app()` or SDK transport factories rather than `create_server()`.
Applications embedding the Python factory must adapt those SDK-specific
calls. Use an isolated environment and an exact version pin when upgrading.

The 49 tools, 34 resources, 32 templates and scientific contracts are
unchanged. Software-version labels and content-derived provenance IDs reflect
the new candidate. Algorithms, numerical inputs, units, defaults and review boundaries
remain unchanged. HTTP retains the explicit 1 MiB limit, Host/Origin checks,
stateless operation and authenticated-gateway startup guard. No telemetry
exporter is enabled. All package artifacts use a new version; the released
v0.1.1 wheel remains the rollback option.

Compatibility evidence compares actual SDK 1.30 and 2.2 clients, released
catalog fingerprints, deterministic intake, seeded probabilistic and
uncertainty calculations, lookup, PBPK/ToxClaw handoffs, monitoring exports
and structured errors. HTTP tests cover invalid headers, untrusted origins,
request limits, parallel requests and two independent app instances.

This is a software infrastructure candidate. OpenFoodTox records remain
`review_required`; independent scientific signoff and promotion remain pending.
MCP Apps, multi-round-trip tools and Tasks are separate future feature work.
No hosted deployment or package-registry publication accompanies this PR.
